# 삐약수학 🐥🔢

유치원(6세)부터 고등학교 3학년까지, 문제를 풀고 레벨을 통과하며 배우는 **개인 학습용 수학 앱**.
판매·배포 없음, 가족용. 병아리 마스코트, 이미지 파일 없이 이모지와 Canvas 로만 그린다.

> 이 저장소는 **삐약공부(영어+수학 통합 앱)에서 분기**해 만든 독립 앱이다.
> 분기 이전의 개발 이력(v1.0~v2.10.1)은 삐약영어 저장소
> (https://github.com/Yongminlee2/EngEdu) 의 README 에 있다.
> 영어는 삐약영어 앱이 맡고, 여기는 수학만 다룬다.

## 빌드·설치

```
$env:GRADLE_USER_HOME='C:/gradle-home'   # 필수! 한글 홈 경로 함정
./gradlew.bat testDebugUnitTest assembleDebug
adb install -r 삐약수학-vX.Y.apk
```

- `applicationId` 는 **`com.peep.math`** (2026-08-05 에 `com.piyak.math` 에서 바꿨다).
  앞으로는 **절대 바꾸지 말 것** — 바꾸면 진행도가 날아간다

  applicationId 만 바꿔 데이터를 분리했다 — 파일을 옮기지 말 것
- 콘텐츠를 재생성(`node tools/gen_math.js`)하면 **반드시 `node tools/gen_index.js`** 도 실행
- 단위테스트는 `GRADLE_USER_HOME` 없이 돌리면 ClassNotFoundException 으로 죽는다

### v1.1: 진짜 수학 기호 + 병아리 리액션 + 문제 우선 화면

사용자 피드백 다섯 가지를 반영했다: 답 선택이 너무 크다 / 계산기 같다 / 캐릭터·애니메이션이

**🔤 FormulaView — 수식을 진짜 수학책처럼**

- `engine/Formula.kt` 파서가 팩의 평문을 토큰 트리로: **세로 분수**(가로줄), **log 아래첨자**,
  **lim 아래 조건**(n→∞), **근호 윗줄**, **∫ 상·하한**. 팩 재생성 없이 기존 텍스트를 그대로 읽는다
- 원칙: 어떤 입력에도 예외 없음 — 못 알아보면 평문 폴백. `FormulaTest` 가 **13,291문제 전수**를
  돌려 예외 0을 보장 (lim 246 · ∫ 120 · log 23 · √ 86 · 분수 772 · 지수 329 검출)
- 생성기에 `tidyCoef` 정규화 추가 — `1x²`·`-1x` 같은 계수 1 흉함을 prompt·해설 전부에서 제거
  (개별 템플릿이 아니라 validate() 에서 일괄 처리 — 새 생성기도 자동 적용)

**🐥 병아리 상주 리액션 (ChickView)**

- 문제 화면 오른쪽 위에 병아리가 늘 있다: 평소 숨쉬기, **정답 점프+하트**, 오답 1초 처짐(금방
  회복 — 기죽지 않게), 15초 무응답이면 응원 말풍선("힘내! 🐥")
- 고등(h1~h3)은 숨김 — 깔끔하게

**🎉 콤보·색종이 + 문제 전환**

## 2026-08-04: 문제·해설까지 12개 언어로 — v1.47

### 왜 팩을 언어별로 복제하지 않았나
가장 단순한 방법은 언어마다 문제 팩을 한 벌씩 굽는 것이다. 그런데 팩이 4.7MB라
12개 언어면 **56MB**가 되고, 문제를 하나 고칠 때마다 12벌을 다시 구워야 한다.

그래서 **문장을 뼈대와 값으로 쪼개는** 방식을 썼다.

```
팩에 저장 :  prompt "3개에 5개를 더하면 8개예요."   ← 한국어 원문(안전망)
             tk "4426d4f7"   ta ["3","5","8"]      ← 뼈대 키 + 값
리소스     :  tpl_4426d4f7(en) = "%1$s plus %2$s makes %3$s."
화면       :  "3 plus 5 makes 8."
```

팩은 1.1MB 늘고 문자열 리소스가 12개 언어 합쳐 0.5MB 늘었다. 총 **+1.6MB**로 끝났다.
번역이 없는 뼈대는 리소스를 못 찾고 **한국어 원문으로 안전하게 떨어진다** —
반쪽짜리 문장이 화면에 뜨는 일은 구조적으로 없다.

### 도구 (`tools/i18n/`)
| 파일 | 하는 일 |
|---|---|
| `keyify.js` | 생성기의 한국어 문장을 훑어 `tp(키, 값들, 원문)` 으로 **자동으로 감싼다**. 키는 뼈대의 해시라 문장을 고치면 키도 따라 바뀐다. 몇 번을 돌려도 같은 결과 |
| `rank.js` | 구워진 팩을 세어 뼈대마다 **실제 출제 빈도**를 매긴다. 많이 쓰이는 것부터 번역했다 |
| `tpl/*.js` | 뼈대 번역 원장 (묶음별로 나눠 둠) |

### v1.48: "번역이 없으면 영어"를 규칙으로 못박음

처음엔 번역이 없으면 **한국어 원문**으로 떨어지게 했다. 안전하긴 해도 영어권
사용자에게는 읽을 수 없는 화면이라, **한국어로 떨어지는 경우 자체를 없앴다.**

- `verify.js` 가 뼈대 없는 문장을 **실패로 처리**한다 (이전엔 숫자만 세고 넘어갔다)
- `gen_strings.js` 는 **영어 번역이 없는 뼈대**가 있으면 빌드를 막는다.
  영어가 없으면 다른 언어도 기댈 곳이 없기 때문이다
- `KoreanLeakTest` — node 없이 **빌드 안에서** 같은 규칙을 검사한다:
  ① 한글 문장에는 tk/ek 가 있다 ② 그 키가 `values/`(영어)에 있다 ③ 기본 리소스가 영어다

게이트를 켜자마자 **실제로 새던 곳을 하나 잡았다.** 판별식 해설은 뼈대가
`D = b² - 4ac = …` 라 한글이 없고, 결론 문장("서로 다른 두 실근")이 **값 쪽에만**
있었다. 코드모드가 "번역할 게 없다"며 키를 안 붙였고, 앱은 조립을 못 해 한국어를
그대로 띄웠다. → 손으로 `tp()` 를 씌운 문장은 **뼈대에 한글이 없어도 무조건 키를
붙이도록** 고쳤다.

### 함정 기록
- **`KINDS` 화이트리스트처럼, 사전에 없는 낱말은 조용히 한국어로 남는다.** 그래서
  `verify.js` 로 전수 검사하는 것이다. 눈으로는 절대 못 잡는다
- 안드로이드는 **리소스 값의 앞뒤 공백을 지운다.** 문장을 이어 붙이는 데 쓰는 공백은
  사전이 아니라 `Tpl.word()` 가 원본에서 되살린다
- 조건문 안에 한국어를 넣으면(`a > b ? "빼면" : "더하면"`) 값이 한국어가 되어 번역이 반쪽이 된다.
  **갈래마다 `tp()` 로 따로 감싸는 것**이 맞다
- **뼈대에 한글이 없어도 방심하지 말 것.** 수식뿐인 문장이라도 결론이 값으로 들어오면
  키가 필요하다. "한글이 보이는지"가 아니라 **"조립이 필요한지"** 로 판단해야 한다

### 말줄임을 자동 축소로 교체

UI 덤프의 `text` 속성은 **화면에서 말줄임되어도 전체 문자열을 그대로 보고한다.**
이걸 믿고 "고쳐졌다"고 판단한 것이 오판이었고, 스크린샷을 보니 러시아어
"Данные и вероятно…" 가 여전히 잘리고 있었다.

언어별로 칸 폭을 재서 맞추는 방식은 14개 언어 × 화면마다 반복해야 해서 끝이 없다.
**칸에 맞춰 글자 크기가 스스로 줄어들게(autoSize)** 바꿨다 — 실력 줄 영역명(10~14sp),
배지 이름(9~12sp)·설명(8~10sp), 문제 유형 라벨(10~13sp).
한국어는 원래 짧아서 최대 크기 그대로라 화면이 하나도 안 바뀐다.

**교훈: 레이아웃 검증은 UI 덤프가 아니라 스크린샷으로 한다.**

**소스 패키지(namespace)는 `com.piyak.english` 그대로다.** 바꾼 것은 `applicationId`
한 줄씩뿐 — 파일을 옮기지 않았다.

**여기서 깨질 수 있었던 것**: 매니페스트가 액티비티를 `.ui.MainActivity` 처럼 상대
이름으로 적는다. 이게 applicationId 기준으로 풀리면 `com.peep.english.ui.MainActivity`
가 되어 앱이 켜지자마자 죽는다. AGP 7+ 는 **namespace 기준**으로 푸는 게 맞지만
추측으로 넘기지 않고 빌드한 APK 의 매니페스트를 열어 확인했다:

```
패키지: com.peep.english
액티비티: com.piyak.english.ui.MainActivity  (…외 12개 전부 com.piyak.english.*)
```

리소스도 같이 확인 — 리소스 표의 패키지 이름이 새 applicationId(`com.peep.english`)로
바뀌었다. `getIdentifier(name, type, context.packageName)` 로 찾아 쓰는 그림·소리가
여기에 의존하므로 중요하다. 개수도 그대로: `sfx 4 · stk 12 · shop 15 · word 1213 · ck 17 · tpl 87`.

**⚠ 폰에서는 전혀 다른 앱이 된다.** 기존에 깔린 `com.piyak.*` 앱은 그대로 남고,
새 패키지는 별도로 설치된다. 진행도·용돈·오답 노트는 **넘어오지 않는다**.
출시 전이라 그대로 두기로 했다.

**⚠ 폰이 빠져 있어 실행은 확인하지 못했다.** 매니페스트·리소스 표 검증까지가 지금 할 수
있는 전부다. 폰을 연결하면 두 앱이 켜지는지부터 볼 것.

### v3.60 / 수학 v1.62 — 아래가 잘리던 두 곳 (사용자 사진으로 확인)

지난 라운드에서 "고쳤다"고 말했지만 **폰이 빠져 있어 화면으로 확인하지 못한 채** 한 말이었다.

**① 레슨 목록의 맨 아랫줄 원**
원(레슨 버튼)의 배경은 그림자를 가진다 — 플랫폼 기본 버튼 스타일(`android:buttonStyle` →

**뷰 바깥**에 그려지는데 안드로이드는 기본으로 자식을 부모 경계에서 잘라낸다(clipChildren).
줄 사이는 vGap 8dp 덕에 자리가 있었지만 **마지막 줄만** 없었다.

지난번엔 FlowLayout 아래 여백만 줬는데, 여백만으로는 부모(unitsBox)가 다시 자를 수 있다.
이번에는 **잘라내기 자체를 껐다** — FlowLayout·unitsBox 에 `clipChildren=false`.
단, ScrollView 는 끄지 않았다 — 끄면 스크롤할 때 내용이 제목줄 위로 삐져나온다.

**② 알파벳 완성 문구가 반쯤 잘림**
`tr_done_coins` = "완성! 용돈 +10원 🎁 · '한 번 더 쓰기'로 연습해요!" 는 **두 줄**인데,
안내문(`ly_trace_hint`, 한 줄) 기준으로 자리가 잡혀 있어 아랫줄이 잘렸다.
`minLines=2 / maxLines=2` 로 두 줄 자리를 못 박고, 더 긴 언어에서는 글자가 스스로
줄어들게(11~15sp 자동 축소) 했다. 그림판(TraceView)은 weight 라 그만큼 줄어든다.

**⚠ 이번에도 폰이 빠져 있어 화면 확인은 못 했다.** 다만 지난번과 달리 원인을 코드에서
확인하고 고쳤다(그림자를 만드는 elevation 이 실제로 있는지, 문구가 실제로 두 줄인지).
폰을 연결하면 이 두 화면부터 볼 것.

### v3.63 / 수학 v1.65 — 잘림의 진짜 원인, 한글이 이모지로 잡히던 버그, 선 잇기 마무리

사용자가 연달아 짚어 준 것들. **한쪽 앱만 고치지 말라**는 지적이 정확했다.

**① 잘림의 진짜 원인은 `clipToPadding` 이었다**
지난번엔 "여백이 없어서"로 보고 아래 여백을 줬는데, **여백을 줘도 소용이 없었다.**
`clipToPadding` 이 기본 `true` 라 안드로이드는 **여백 안쪽에서** 자르기 때문이다.
낱말 배열 문제의 타일 상자는 이미 8dp 여백이 있었는데도 맨 아랫줄이 잘려 있던 게 증거다.

호출하는 곳마다 고치는 대신 **`FlowLayout` 자체가 절대 자르지 않게** 했다
(`clipChildren=false` + `clipToPadding=false`). 이 한 곳으로 두 앱의 모든 사용처가
덮인다 — 레슨 목록의 원, 낱말 배열 타일, 앞으로 생길 것까지.

**② 한글이 이모지로 분류되어 글자가 커지던 버그**
선 잇기·버블·풍선이 이모지를 `text[0].code > 0x2000` 으로 판별했다.
**한글은 U+AC00 부터라 전부 여기 걸린다.** 그래서 한글 보기는
이모지용 큰 크기(0.55배)로 그려지고, 폭에 맞춰 줄이는 처리(`if (!isEmoji …)`)까지
건너뛰었다 — 영어 옆에서 한글만 유독 커 보이던 원인.
`isEmojiText()` 로 바꿔 그림문자 평면(U+1F000~)과 기호 구간만 이모지로 본다.
두 앱의 LineMatchView·BubbleChoiceView·BalloonGameView 전부.

**③ 선 잇기: 마지막 짝을 이으면 즉시 다음 판**
`if (isCleared) onFinish?.invoke()` 가 그 자리에서 판을 갈아치워 맞았는지 볼 틈이 없었다.
네 줄이 다 초록으로 이어진 모습을 **0.9초 보여 준 뒤** 넘어가게 했다.

**④ 힌트: 영어 앱만 아무 반응이 없었다**
수학 앱은 못 쓰는 이유를 알려 주는데(이미 씀 / 4지선다 전용 / 없음), 영어 앱은
버튼을 비활성화만 해서 왜 안 되는지 알 수 없었다. 수학 방식으로 맞추고
안내 문구 2개를 영어 원장에 옮겨 왔다. 기능 자체(상점 구매 → 오답 2개 지우기)는
두 앱 다 정상.

**⚠ 폰이 빠져 있어 ①~③은 화면으로 확인하지 못했다.**

내비게이션 바가 '확인' 버튼을 덮었다.

**원인은 edge-to-edge 강제다.** `targetSdk = 36` 이라 안드로이드 15(API 35)부터는
앱을 **시스템 바 뒤까지** 그리게 강제한다. 앱이 인셋만큼 여백을 스스로 주지 않으면 겹친다.
**안드로이드 14 이하에는 이 강제가 없어 멀쩡해 보인다** — 그래서 S20(안드로이드 13)으로만
확인하던 검증에서 통째로 빠져나갔다. 구형 기기 한 대만으로는 이 부류를 절대 못 잡는다.

**화면마다 고치지 않고 `PiyakApp` 한 곳에서 처리했다.** 화면이 13개라 하나씩 넣으면
빠뜨리고, 앞으로 만들 화면에서도 또 빠진다.

```kotlin
registerActivityLifecycleCallbacks(...)   // 모든 액티비티의 content 루트에
  systemBars() or displayCutout() or ime() // 만큼 padding
```

**키보드(ime)도 함께 넣었다.** edge-to-edge 에서는 `adjustResize` 가 먹지 않아
쓰기 문제에서 키보드가 입력칸을 덮는 같은 원인의 버그가 있었다(화면으로는 아직 못 봤다).

테마에 `windowLightNavigationBar` 도 추가 — 크림 배경 위라 내비게이션 바 아이콘이
어두워야 보인다.

**⚠ 안드로이드 15 기기가 없어 화면으로 확인하지 못했다.** 빌드·테스트는 통과했고
수정 자체는 표준적인 방식이지만, 실제로 겹침이 사라졌는지는 그 폰에서 봐야 한다.

# 🐥 이어서 개발하는 사람에게 (Codex·새 세션용)

개발일지는 위에 시간순으로 다 있다. 여기는 **읽지 않으면 사고가 나는 것**만 모았다.
작업 전에 이 절만은 처음부터 끝까지 읽을 것.

## 절대 규칙

| 규칙 | 어기면 |
|---|---|
| **커밋 메시지에 AI 표기(Co-Authored-By, Generated with 등)를 넣지 않는다** | 사용자가 명시적으로 금지했다. 과거 커밋 87개를 지우는 작업을 따로 해야 했다 |
| **빌드는 `GRADLE_USER_HOME=C:/gradle-home` 로** | 홈 경로에 한글이 있어 그냥 돌리면 Gradle 워커가 죽는다 |
| **`applicationId` 를 바꾸지 않는다** | 바꾸면 새 앱이 되어 사용자 진행도가 전부 사라진다. 이미 스토어에 올라가 있다 |
| **소스 패키지(`namespace`)는 `com.piyak.english`** — 두 앱 다 그렇다 | 파일을 `com/peep/...` 로 옮기지 말 것. applicationId 만 `com.peep.*` 다 |
| **폰 설치는 사용자가 요청할 때만** | adb 를 백그라운드로 대기시키지 말 것 |
| **`codex-restyle`·`backup-before-msg-cleanup` 브랜치를 머지하지 않는다** | 전자는 미채택 리스타일(디자인이 뒤집힌다), 후자는 커밋 메시지 정리 **전** 이력이다 |

## 두 저장소 체제 — 공용 코드는 양쪽 다 고쳐야 한다

`C:\workAndroid\PiyakEnglish` 와 `C:\workAndroid\PiyakMath` 는 **소스가 복제돼 있다.**
`Db` · `Sfx` · `Tts` · `Wallet` · `BubbleChoiceView` · `LineMatchView` · `FlowLayout` ·
`PiyakApp` · `StatsActivity` … 는 파일이 각각 따로 있다.

**한쪽만 고치면 다른 앱에 버그가 남는다.** 실제로 여러 번 그랬다(사용자가 "왜 수학은 안 고쳐?"
라고 지적한 적 있음). 공용 파일을 건드렸으면 반대쪽 저장소에서 같은 파일을 확인할 것.

## 생성물을 직접 고치지 말 것

| 파일 | 진짜 원본 |
|---|---|
| `app/src/main/res/values*/strings.xml` | `tools/i18n/` 의 원장 → `node tools/i18n/gen_strings.js` |
| `tools/i18n/ui_rest.js` · `ui_home.js` · `ui_skills.js` | `make_ui_*.js` 의 `COPY`/`EXTRA` |
| `app/src/main/assets/packs/*.json` | `tools/gen.js`(영어) · `tools/gen_math.js`(수학) |

생성물을 직접 고치면 **다음 생성 때 조용히 사라진다.** 실제로 영어 전용 키 25개를 그렇게
날렸다가 빌드 실패로 발견했다. `EXTRA` 는 백틱 템플릿이라 `\n` 을 넣으려면 역슬래시를 한 겹 더.

콘텐츠를 재생성하면 **반드시 함께 돌릴 것**: `node tools/gen_index.js`,
그리고 영어는 `node tools/i18n/tag_titles.js`(안 돌리면 제목 번역이 죽는다),
`node tools/gen_wordart.js`(낱말 그림 색인).

## 릴리스에서만 터지는 것들

**① 이름으로 부르는 리소스는 잘린다.**
`resources.getIdentifier("word_apple", ...)` 처럼 이름을 조합해 찾는 리소스는
`shrinkResources` 가 "안 쓴다"고 보고 지운다. **소리(`res/raw`)도 똑같이 지워진다.**
새로 만들면 `res/raw/keep.xml` 에 패턴을 넣고, 릴리스 빌드 후 개수를 셀 것:

```bash
aapt2 dump resources app-release.apk | grep -c 'raw/sfx'
```

디버그로는 절대 재현되지 않는다. 실제로 효과음 4종이 통째로 잘려 출시본이 무음이 될 뻔했다.

**② 안드로이드 15+ 는 시스템 바 뒤까지 그리게 강제한다(edge-to-edge).**
`PiyakApp.fitSystemBarsEverywhere()` 가 모든 액티비티 루트에
`systemBars + displayCutout + ime` 만큼 padding 을 준다. **이 처리를 지우지 말 것.**
안드로이드 14 이하에서는 강제가 없어 멀쩡해 보이므로 **구형 기기 검증으로는 못 잡는다.**
UI 를 건드렸으면 안드로이드 15 이상 기기에서 볼 것.

## 검증에서 반복해 속은 것

- **UI 덤프(`uiautomator dump`)의 `text` 는 화면에서 잘려도 원문을 그대로 준다.**
  잘림·겹침 판정은 **반드시 스크린샷을 눈으로** 볼 것. 이 폰에서는 덤프가 이전 화면을
  보고하는 일도 잦다 — 그럴 땐 좌표로 직접 조작할 것.
- **빌드 통과 ≠ 동작.** 테스트가 다 녹색인데 정답이 전부 1번이던 적이 있다.
- 스크린샷 탭 좌표는 **매번 배율을 곱할 것**(읽은 이미지 900px ↔ 실제 1080px).

## 스토어에 손댈 때

- **광고·인앱결제·무료 이야기를 등록정보에 한 줄도 쓰지 않는다.** 나중에 붙일 계획이라
  지금 "없음"이라고 쓰면 그때 거짓말이 된다. 반대로 **데이터 보안·콘텐츠 등급 신고**는
  올리는 빌드의 실제 모습대로 적어야 한다(신고와 앱이 다르면 앱이 내려간다).
- **대상 연령을 13세 이상으로 신고했다.** 그래서 등록정보·legal 페이지에서
  "아이가 / 부모가 / 유치원생 대상" 같은 **대상을 지목하는 표현**을 전부 걷어냈다.
  커리큘럼 범위("알파벳부터", "수 세기부터")는 사실이라 남겼다. 새 문구를 쓸 때 이 선을 지킬 것.
- **TOEIC·TOEFL 은 ETS 등록상표다.** 등록정보에 쓰지 말 것("시험 대비" 로 표현).
- 개인정보처리방침·소개·지원 페이지는 **공개 저장소** `github.com/Yongminlee2/legal` 의
  `peepenglish/` `peepmath/` 에 있다. 이 저장소가 비공개가 되어도 스토어가 읽어야 하므로
  그쪽에 둔 것이다. 앱 문구를 바꾸면 거기도 같이 고칠 것.
