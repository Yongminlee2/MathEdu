# 삐약수학 🐥🔢

유치원(6세)부터 고등학교 3학년까지, 문제를 풀고 레벨을 통과하며 배우는 **개인 학습용 수학 앱**.
판매·배포 없음, 가족용. 병아리 마스코트, 이미지 파일 없이 이모지와 Canvas 로만 그린다.

> 이 저장소는 **삐약공부(영어+수학 통합 앱)에서 분기**해 만든 독립 앱이다.
> 분기 이전의 개발 이력(v1.0~v2.10.1)은 삐약영어 저장소
> (https://github.com/Yongminlee2/EngEdu) 의 README 에 있다.
> 영어는 삐약영어 앱이 맡고, 여기는 수학만 다룬다.

## 빌드·설치

```
$env:GRADLE_USER_HOME='C:/gradle-home'   # 필수! 한글 홈 경로 함정
./gradlew.bat testDebugUnitTest assembleDebug
adb install -r 삐약수학-vX.Y.apk
```

- `applicationId` 는 `com.piyak.math` — **절대 바꾸지 말 것** (바꾸면 진행도가 날아간다)
- 소스 패키지(namespace)는 `com.piyak.english` 그대로다. 분기하면서 소스 이동 없이
  applicationId 만 바꿔 데이터를 분리했다 — 파일을 옮기지 말 것
- 콘텐츠를 재생성(`node tools/gen_math.js`)하면 **반드시 `node tools/gen_index.js`** 도 실행
- 단위테스트는 `GRADLE_USER_HOME` 없이 돌리면 ClassNotFoundException 으로 죽는다

## 개발 일지

### v1.1: 진짜 수학 기호 + 병아리 리액션 + 문제 우선 화면

사용자 피드백 다섯 가지를 반영했다: 답 선택이 너무 크다 / 계산기 같다 / 캐릭터·애니메이션이
없다 / 수식이 그냥 텍스트다 / 풀 때 실감이 없다.

**🔤 FormulaView — 수식을 진짜 수학책처럼**

- `engine/Formula.kt` 파서가 팩의 평문을 토큰 트리로: **세로 분수**(가로줄), **log 아래첨자**,
  **lim 아래 조건**(n→∞), **근호 윗줄**, **∫ 상·하한**. 팩 재생성 없이 기존 텍스트를 그대로 읽는다
- 원칙: 어떤 입력에도 예외 없음 — 못 알아보면 평문 폴백. `FormulaTest` 가 **13,291문제 전수**를
  돌려 예외 0을 보장 (lim 246 · ∫ 120 · log 23 · √ 86 · 분수 772 · 지수 329 검출)
- 생성기에 `tidyCoef` 정규화 추가 — `1x²`·`-1x` 같은 계수 1 흉함을 prompt·해설 전부에서 제거
  (개별 템플릿이 아니라 validate() 에서 일괄 처리 — 새 생성기도 자동 적용)

**🐥 병아리 상주 리액션 (ChickView)**

- 문제 화면 오른쪽 위에 병아리가 늘 있다: 평소 숨쉬기, **정답 점프+하트**, 오답 1초 처짐(금방
  회복 — 기죽지 않게), 15초 무응답이면 응원 말풍선("힘내! 🐥")
- 고등(h1~h3)은 숨김 — 깔끔하게

**🎉 콤보·색종이 + 문제 전환**

- 정답 색종이(5연속↑ 증가), 2연속부터 **🔥 N연속!** 배지. 오답이면 조용히 리셋
- 문제 전환: 이전 문제 왼쪽 슬라이드아웃(90ms) → 새 문제 오른쪽 슬라이드인(110ms)

**📐 답 영역 컴팩트** — 버블판 280→180dp, 선다 버튼 76→60dp, 키패드 52→44dp.
문제·그림이 그만큼 커졌다. 단위테스트 64건 전부 통과.

## 2026-08-04: 문제·해설까지 12개 언어로 — v1.47

### 왜 팩을 언어별로 복제하지 않았나
가장 단순한 방법은 언어마다 문제 팩을 한 벌씩 굽는 것이다. 그런데 팩이 4.7MB라
12개 언어면 **56MB**가 되고, 문제를 하나 고칠 때마다 12벌을 다시 구워야 한다.

그래서 **문장을 뼈대와 값으로 쪼개는** 방식을 썼다.

```
팩에 저장 :  prompt "3개에 5개를 더하면 8개예요."   ← 한국어 원문(안전망)
             tk "4426d4f7"   ta ["3","5","8"]      ← 뼈대 키 + 값
리소스     :  tpl_4426d4f7(en) = "%1$s plus %2$s makes %3$s."
화면       :  "3 plus 5 makes 8."
```

팩은 1.1MB 늘고 문자열 리소스가 12개 언어 합쳐 0.5MB 늘었다. 총 **+1.6MB**로 끝났다.
번역이 없는 뼈대는 리소스를 못 찾고 **한국어 원문으로 안전하게 떨어진다** —
반쪽짜리 문장이 화면에 뜨는 일은 구조적으로 없다.

### 도구 (`tools/i18n/`)
| 파일 | 하는 일 |
|---|---|
| `keyify.js` | 생성기의 한국어 문장을 훑어 `tp(키, 값들, 원문)` 으로 **자동으로 감싼다**. 키는 뼈대의 해시라 문장을 고치면 키도 따라 바뀐다. 몇 번을 돌려도 같은 결과 |
| `rank.js` | 구워진 팩을 세어 뼈대마다 **실제 출제 빈도**를 매긴다. 많이 쓰이는 것부터 번역했다 |
| `tpl/*.js` | 뼈대 번역 원장 (묶음별로 나눠 둠) |
| `words_i18n.js` | 값에 박혀 오는 낱말·구절 (사과·삼각형·요일·아이 이름…) |

### v1.48: "번역이 없으면 영어"를 규칙으로 못박음

처음엔 번역이 없으면 **한국어 원문**으로 떨어지게 했다. 안전하긴 해도 영어권
사용자에게는 읽을 수 없는 화면이라, **한국어로 떨어지는 경우 자체를 없앴다.**

- `verify.js` 가 뼈대 없는 문장을 **실패로 처리**한다 (이전엔 숫자만 세고 넘어갔다)
- `gen_strings.js` 는 **영어 번역이 없는 뼈대**가 있으면 빌드를 막는다.
  영어가 없으면 다른 언어도 기댈 곳이 없기 때문이다
- `KoreanLeakTest` — node 없이 **빌드 안에서** 같은 규칙을 검사한다:
  ① 한글 문장에는 tk/ek 가 있다 ② 그 키가 `values/`(영어)에 있다 ③ 기본 리소스가 영어다

게이트를 켜자마자 **실제로 새던 곳을 하나 잡았다.** 판별식 해설은 뼈대가
`D = b² - 4ac = …` 라 한글이 없고, 결론 문장("서로 다른 두 실근")이 **값 쪽에만**
있었다. 코드모드가 "번역할 게 없다"며 키를 안 붙였고, 앱은 조립을 못 해 한국어를
그대로 띄웠다. → 손으로 `tp()` 를 씌운 문장은 **뼈대에 한글이 없어도 무조건 키를
붙이도록** 고쳤다.

### 함정 기록
- **`KINDS` 화이트리스트처럼, 사전에 없는 낱말은 조용히 한국어로 남는다.** 그래서
  `verify.js` 로 전수 검사하는 것이다. 눈으로는 절대 못 잡는다
- 안드로이드는 **리소스 값의 앞뒤 공백을 지운다.** 문장을 이어 붙이는 데 쓰는 공백은
  사전이 아니라 `Tpl.word()` 가 원본에서 되살린다
- 조건문 안에 한국어를 넣으면(`a > b ? "빼면" : "더하면"`) 값이 한국어가 되어 번역이 반쪽이 된다.
  **갈래마다 `tp()` 로 따로 감싸는 것**이 맞다
- **뼈대에 한글이 없어도 방심하지 말 것.** 수식뿐인 문장이라도 결론이 값으로 들어오면
  키가 필요하다. "한글이 보이는지"가 아니라 **"조립이 필요한지"** 로 판단해야 한다
